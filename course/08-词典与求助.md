# 反馈与求助｜让 AI 知道要修什么

AI Coding 的关键动作包括表达目标、判断结果和根据反馈推进。遇到问题时，先说清“做了什么、期待什么、实际发生什么”。

## 先判断：想法变了，还是结果没做到

| 情况 | 去哪里继续 | 怎样处理 |
| --- | --- | --- |
| 想新增功能、改规则或改操作方式 | Gemini 与 Canvas | 更新 PRD 和设计，试用确认后再交 Trae 开发 |
| 真实作品与确认设计不一致 | Trae | 提供具体现象，修复后按同样动作复测 |
| 原型操作不顺或提示看不懂 | Gemini Canvas | 调整设计；若改变规则，同时更新 PRD |
| 电脑工具无法启动、安装或授权遇到提示 | Trae | 提供当前画面，按它指引完成本人动作 |

不确定时先让助手判断当前是哪种情况，不必自己定位代码。

## 给出具体反馈

```text
我现在在【阶段】的【页面】做了【动作】。原本希望【结果】，实际看到【现象】。请先检查这是实现偏差还是需要更新需求。实现问题请修复并给我同样动作的复试步骤；需求改变请指导我先更新 PRD 和 Canvas 设计。需要我本人操作时，一次给一个动作。
```

例如：“我新增一条记录并保存，刷新后不见了；需求里说刷新后应该保留。请修复，再让我按相同动作检查。”

如果有报错，提供完整文字或画面。遮住密码、调用凭证和私人资料。描述可观察现象，不需要猜测技术原因。

## AI 给出看不懂的说明时

```text
请先用日常语言告诉我这一步是为了什么、我需要做什么、成功后会看到什么。具体技术配置由你按已准备的方案处理。
```

## AI 说已经完成时

```text
请给我实际试用入口和检查步骤，并说明每步预期结果。哪些是模拟、哪些实际验证过、哪些还没验证，请分别说清。我按步骤试过后再确认本轮完成。
```

## 第二天或新对话继续时

```text
请读取这个作品已有的需求、设计和进度，告诉我本轮目标、已完成什么、尚未验证什么，以及下一步让我做什么。若这轮还没有确认需求或设计，先引导我补齐；已确认的材料继续使用。
```

## 必要工具与材料：只需知道用途

| 工具或材料 | 用途 |
| --- | --- |
| Gemini | 讨论使用场景、整理和更新需求 |
| Canvas | 在开发前试用设计，每版都更新 |
| Trae | 建立项目，读取确认材料，分步实施和检查 |
| Docker Desktop | 启动预装开发工具箱，可供多个作品使用 |
| 课程助手（Skill） | 给 AI 的工作说明，技术选择由它处理 |
| 项目工程 | 保存当前作品材料、实现内容与进度的独立工作空间 |
| PRD.md | 本轮确认的需求说明，用日常语言写 |
| HTML 设计文件 | Canvas 导出的可点击设计，后续照它实现 |
| CloudBase | 让作品联网保存和共享内容的服务 |
| APK 安装文件 | 用来把作品安装到安卓手机 |
| AI 调用凭证 | 授权作品使用 AI 的秘密钥匙，只在指定位置本人填写 |

知道用途、找到入口、完成当前动作就可以继续。这些名称不用背诵。
